# 控制逻辑待解决事项

这是原实验控制代码的整理版本，以下问题没有因文件拆分自动解决。

| 问题 | 当前行为与影响 | 后续方向 |
|---|---|---|
| 中止不取消已提交运动 | ABORTED 停止后续发布，不发送急停或取消请求；驱动可能继续已收到的运动 | 按实际厂商接口设计并验证停止、取消及故障恢复 |
| 夹爪动作早于完整验证 | `--execute` 后可能先归一化夹爪，再获取稳定视觉目标和完成 IK | 明确初始化阶段，按设备需求重新安排动作前检查 |
| 没有碰撞规划 | 数值 IK、关节限制和 TCP 边界无法检查障碍物或自碰撞 | 加入环境/机器人碰撞检查或规划系统 |
| 抓取几何依赖安装 | 依据相机朝向模型中心和指定距离还原 TCP；并非直接求解夹爪接触点 | 为物体与夹爪定义独立抓取坐标和策略 |
| 目标冻结后的视觉恢复策略 | 开始抓取后冻结目标，视觉恢复事件不会自动中止整个已启动抓取 | 区分预期遮挡、目标移动和跟踪失败，明确各阶段策略 |
| 未验证闭合兼容选项 | 历史 `--allow-unverified-close-fallback` 可放宽闭合验证，默认未开启 | 完成真实反馈校验后再决定是否保留 |
| 闭合超时参数需复核 | 原闭合 fallback 超时约 3 秒，而通用命令超时约 7 秒，可能提前结束等待 | 使用实测反馈确定统一的超时和成功判据 |
| 时间同步只有最近邻 | 手眼桥不插值；时间窗内也可能有移动误差，时钟不一致同样会失败 | 验证共同时间基准并评估插值/运动误差 |
| 设备参数不能复用承诺 | 行程、homing、关节名字、外参和物体配置源于原设备 | 使用本机标定、固件与 URDF 重新验证 |

模板确认标志只防止意外直接使用占位配置，不证明标定正确。35 项 CPU 测试覆盖纯函数和历史数值回归；不覆盖实际 CAN、设备停止响应或硬件动作效果。
